# Kevala 0.2.1

Kevala 0.2.1 packages the GPU runtime changes that landed after 0.2.0.

## Changes

- The shared Qwen3.5 runtime calibrates projections by precision and validates loaded-weight outputs before selecting faster single-row matrix-vector kernels.
- Clef-flash keeps token embeddings on the GPU and caches lexical option means. Warm requests avoid embedding and lexical readback.
- Gemma 4 extends optional gate/up fusion to suffix lengths 97–112, with bounded calibration reuse. Numerical and timing checks retain the baseline when a candidate does not qualify.
- CI uses updated Rust toolchain and pnpm setup actions. Loading instructions explain how to use the website runtime with older npm versions.

## Validation and limits

The [October 30 runtime campaign](../projection-runtime-validation.md) exercised all 11 catalog models with local Q8 packs and the available smaller BF16 variants on Firefox WebGPU. It checked answer types, normalized probabilities, repeated calls, and batched calls. These are runtime and regression checks, not model accuracy results.

Clef's paired check matched hidden values, WASM head inputs, and public answers exactly. The Qwen kernel checks do not establish an ordinary-request latency gain. The Gemma image checks passed numerical guards, but their timing gates retained the baseline, so they do not establish a camera FPS gain.

Kev-9B BF16 and larger Clef configurations remain limited by the available validation hardware. Other GPUs and browsers need separate measurements. The existing 60 FPS camera target remains unmet.

## Package scope

The npm package contains the browser and Node runtime and three WebAssembly flavors. Model weights remain separate packs. This release does not include a native macOS CLI binary.
