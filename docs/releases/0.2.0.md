# Kevala 0.2.0

Kevala 0.2.0 updates the browser and Node runtime, its model catalog, and the Reaction Recorder image path. Model weights remain separate `.kevala` packs; the npm package does not include them.

## Highlights

- **Model catalog and precision:** Refreshes the Kev catalog and adds H2O-Lightning-4B and Cloudflare Clef-flash. Updated Kev and new model conversions default to BF16, with Q8 available as an explicit smaller-pack option. Some catalog entries still require a converted pack URL because their packs are not published.
- **Catalog compatibility:** Retires Bruv from the active catalog while retaining its historical benchmark evidence. Use an active catalog model for new requests. Refreshed BF16 defaults require more storage and memory than Q8; request `precision: "q8"` when that is the intended format.
- **Reaction Recorder:** Adds a webcam demo that runs the Gemma 4 E2B vision companion and reports per-frame scores for visible people and expressions. Scores are uncalibrated and describe visible cues, not a person's inner mood. The picker filters to models with an implemented image companion while this tab is selected. Gemma 4 E2B is the supported image model in this release; the other registered model families remain text-only in Kevala.
- **Camera and vision path:** Adds GPU image preparation, latest-frame scheduling, decoder caches, and guarded fusions across the vision encoder and decoder. Safari loads avoid cloning file handles through worker messages. The numerical guards retain the reference path when compatibility or tolerance checks fail.
- **Shared kernels:** Improves WebGPU matrix, attention, recurrence, and Gemma execution, with CPU kernel selection and numerical guards. See the [performance reports](../README.md#kernel-optimization-reports) for the hardware and correctness checks behind individual changes.
- **Release checks:** CI validates the generated WebAssembly and the packed npm artifact. The release candidate artifact is retained for seven days; CI does not publish it.
- **GPU guards:** Laya's same-pack WASM/WebGPU comparison now runs separately from Q8-versus-PyTorch accuracy. The suite also validates the registered vision QKV and grid MLP kernels and records unsupported device limits explicitly.

## Performance evidence

The latest controlled Fast-mode comparison measured 42.61 to 44.17 completed decisions per second, a 3.67% increase, on Linux with an RTX 5070 Ti and Chromium. It used synthetic changing camera frames and is not a sensor-to-screen measurement. The 60 FPS target remains unmet, and M4 Max camera performance has not been measured. Earlier Balanced and Detail figures in the [Gemma 4 fusion report](../gemma4-fusion-performance.md) came from separate checkpoints and are not a direct before-and-after comparison.

These measurements establish runtime throughput for the recorded setup, not general expression-classification accuracy or performance on every GPU.

## Package scope

The npm package contains the browser and Node runtime and its generated WebAssembly flavors. It does not include model weights or a native macOS CLI binary. Image inference currently requires the separately loaded Gemma 4 E2B vision companion and WebGPU.
